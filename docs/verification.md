# 제품 검증 기준

현재는 최소 정적 페이지, 데이터·설정 모델, 빌드 시 로더와 검사 도구가 구현되어 있다. 날짜·재직 여부, YAML 작성·오류 안내, 경력 콘텐츠 변환, 필수 콘텐츠·빈 값·링크·이미지 입력, Markdown·YAML 핵심 변환, 설정·로더의 단위 테스트가 있다. 브라우저 자동화는 아직 없다.

## 요구사항 대응표

데이터 계약과 로더는 구현되어 있다. D2의 필수 텍스트 누락·빈 값·날짜 형식·용도별 링크 규칙과 O2의 재직·기간 데이터 규칙은 단위 테스트로 검증하며, YAML 링크·기술 매핑 및 섹션 생략, 오류의 필드 경로, 중복 키의 행·열 안내도 검증한다. 경력의 요약만·프로젝트만·둘 다 있는 입력에서 내용 분리와 역할 생략도 검증한다. 로고·배지의 주소·대체 텍스트 검증과 변환, 이미지·확인 링크 생략도 검사한다. 이미지와 링크의 실제 접근 가능 여부, O1의 화면 정렬과 A1의 렌더링된 대체 텍스트는 확인하지 않았다. 나머지 데이터 동작은 미검증이다. 화면 관련 항목은 미구현·미검증이다. 아래는 논의할 후보이며 테스트 코드의 사전 승인이 아니다.

| ID | 확인할 동작 | 제안 수단 |
|---|---|---|
| D1 | YAML 교체로 이름·소개·회사·프로젝트 변경; UI에 샘플 잔존 없음 | 빌드 통합 + 브라우저 |
| D2 | 필수값 누락·빈 문자열·잘못된 날짜·링크 거부. 콘텐츠 ID 검증은 사용하지 않음 | Vitest |
| D3 | 공급·검증 오류가 빌드 실패로 전파; 빈 데이터·샘플 대체 없음 | Vitest + 실패 빌드 |
| D4 | 강조는 strong으로 표현; 일반 텍스트의 HTML 문자를 실행하지 않음 | 렌더 결과 |
| S1 | 제목·순서·visible 설정과 DOM 일치; 프로필 상단 고정 | 브라우저 |
| S2 | 빈/숨긴 섹션의 제목·구분선·여백 생략 | 브라우저 + 시각 검토 |
| E1 | 프로젝트만·요약만·둘 다 있는 경력의 내용을 한 번씩 표시 | 렌더 결과 |
| E2 | 제목→제품 소개→역할→성과→기술·링크 순서와 제목 계층 | 렌더 결과 |
| O1 | 로고·배지·날짜·링크·역할 없이 정렬 유지; 빈 링크 없음 | 브라우저 + 시각 검토 |
| O2 | 종료일 없음과 현재 재직 구분; 미제공 날짜·개월 수 없음 | Vitest + 렌더 결과 |
| T1 | 테마 폰트·크기·굵기·줄 높이·간격·색상·너비 변경이 실제 스타일에 반영 | 브라우저 computed style |
| R1 | 320·390·768·1440px에서 긴 한글/영문 제목·URL·문단·많은 태그·연락처 넘침 없음 | Playwright + 시각 검토 |
| R2 | 모바일에서 섹션명 위·내용 아래; 배치와 읽기 순서 일치 | 브라우저 |
| A1 | 제목·목록·링크 이름·대체 텍스트·lang·대비 | axe + 수동 |
| A2 | Tab 순서·포커스·링크 활성화·확대 200% 가독성 | 수동 키보드/확대 |
| B1 | JavaScript 비활성화에서도 읽기 가능; 불필요한 외부 요청 없음 | 브라우저 |
| B2 | fixture·참고 PDF가 배포물에 없음; 데이터 변경은 재빌드로 반영 | 산출물 확인 + 빌드 비교 |

## 검사 명령

| 명령 | 역할 |
|---|---|
| npm run check | astro check: Astro·TypeScript 검사 |
| npm run lint | Biome lint |
| npm run format:check | Biome format 검사, 수정 없음 |
| npm run format | 명시적 포맷 수정; 미승인 테스트 변경 제외 |
| npm test | 승인된 Vitest 테스트 |
| npm run test:e2e (예정) | 승인된 Playwright 테스트 |
| npm run build | 정적 빌드 |
| npm run verify:static | 현재 제공하는 타입·lint·포맷 검사·빌드. 테스트는 포함하지 않음 |
| npm run verify:commit | 타입·lint·포맷·Vitest 검사; pre-commit에서 실행 |
| npm run verify | verify:commit 통과 후 정적 빌드 |
| npm run prepare | 이 저장소의 Husky hook 등록 |

Vitest는 `src/models/resume.test.ts`의 날짜·재직 여부와 `src/data/yaml-source.test.ts`의 YAML 작성·오류 안내, `src/data/experience-content.test.ts`의 경력 콘텐츠 분리와 역할 생략, `src/data/input-validation.test.ts`의 필수 콘텐츠·빈 값·링크·이미지 입력을 검사한다. 입력 오류는 예외 종류와 작성 필드 경로를 확인하고 정상 입력은 공통 모델 검증 후 값 보존을 확인한다. 테스트 파일이 없으면 실패하며 passWithNoTests를 사용하지 않는다.

`src/data/markdown-yaml.test.ts`는 서식·중첩·공백 보존, 문단형·목록형 소개, HTML·표·실행 URL 오류의 프로젝트 필드 경로, 연락처 매핑을 7개 사례로 검사한다. D4의 데이터 변환을 확인하며 실제 HTML 렌더링과 실행 방지는 검증하지 않았다.

`src/data/resume.test.ts`와 `src/data/local-source.test.ts`는 설정값 보존과 선택 목록 정규화, 섹션 중복·누락 및 테마 오류 경로, 콘텐츠 타입 오류의 원본 값 미노출, 공급 오류 전파, 빈 YAML 오류를 10개 사례로 검사한다. 설정·공급 모듈 또는 YAML 원문을 mock하며 실제 파일 누락과 실패 빌드 재현은 아직 검증하지 않았다.

잘못된 입력을 오류로 처리해야 해당 테스트가 통과한다. 실제 config의 검증 오류는 정적 페이지 생성 중 빌드로 전파된다. `npm run build` 자체는 Vitest를 실행하지 않으며 전체 검증은 `npm run verify`로 수행한다.

Husky의 pre-commit은 verify:commit을, pre-push는 build를 실행한다. commit-msg는 한글 커밋 제목 형식을 검사한다. hook 직접 실행으로 기존 86개 테스트·정적 검사·빌드 통과, 정상 제목 통과와 빈 제목의 종료 코드 1을 확인했다. 별도 hook 테스트 코드 대신 직접 실행으로 연결을 확인하며, 원격 push는 수행하지 않았다.

Astro build는 타입 검사를 대체하지 않는다. Biome는 TS·JSON·CSS·Astro 및 Tailwind 구문을 대상으로 설정한다. Astro 전체 지원은 실험적이므로 명시적으로 활성화하고 적용 범위를 확인한다. 재현된 오탐만 해당 규칙·파일 범위로 제한해 사유를 기록한다.

Vitest는 데이터·정규화 규칙, Playwright는 실제 빌드 화면, axe는 접근성 자동 검사를 담당한다. 브라우저 fixture는 테스트 전용 빌드에 격리하고 일반 배포 경로에 노출하지 않는다. 초기 스크린샷은 수동 검토 증거로 사용하며 자동 시각 회귀 기준은 별도 코드 검토 후 도입한다.

coverage 숫자보다 요구사항 대응표의 누락을 우선 확인한다. 미작성 항목을 빈 테스트나 passWithNoTests로 통과 처리하지 않는다.

## YAML 전환 검증 범위

기존 날짜·재직 여부 테스트는 유지한다. 링크·기술·연락처 매핑, 섹션 생략, 필드 오류와 중복 키 위치, 경력 콘텐츠 분리, 필수 텍스트·빈 값·링크·이미지 입력을 검증한다. Markdown은 서식·중첩·공백과 소개 문단·목록 변환, HTML·표·실행 URL 오류를 핵심 사례로 검증한다. 줄바꿈 문법별 검사와 URL 종류별 반복 검사는 추가하지 않는다. 로더의 빈 YAML·콘텐츠 타입 오류의 원본 값 미노출·공급 오류 전파도 검증한다. 실제 실패 빌드와 배포 산출물 검사는 남아 있다.

Biome 검사 범위에는 src 아래 YAML도 포함한다. 정상 빌드 성공과 오류 입력에 대한 실패 빌드 검증을 구분한다. 기본 빌드의 배포 자산에 원본 YAML이나 테스트 fixture가 노출되지 않는지도 확인한다.
