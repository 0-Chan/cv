# 변경 검증

경로는 저장소 루트 기준이다. AGENTS.md, docs/work-log.md, docs/verification.md를 읽고 실제 패키지 명령의 존재 여부를 확인한다.

1. 변경에 해당하는 요구사항 ID와 완료 기준을 고른다. 미구현 단계는 구분한다.
2. 존재하는 도구와 승인된 테스트를 실행한다. 새 테스트·임시 검증 코드가 필요하면 먼저 시나리오와 코드 초안 검토를 거친다.
3. UI는 실제 빌드 화면의 뷰포트·키보드·장문·선택값 조건을 확인한다. 정적 검사만으로 화면 검증 완료를 주장하지 않는다.
4. 실패를 제품·테스트·환경 문제로 구분한다. 테스트 완화·삭제·snapshot 갱신을 임의로 하지 않는다.
5. 명령, 환경, 결과, 증거, 미검증 사항을 작업 기록에 남기고 다음 검토 대상을 보고한다.

하네스 단계는 문서·참조·frontmatter·링크가 대상이다. 스킬 인식과 실제 동작은 각각 증거가 있을 때만 완료로 기록한다. 앱·테스트가 없으면 미구현·미검증으로 보고한다.

현재 단계 완료 후 다음 단계를 자동 실행하지 않는다.
