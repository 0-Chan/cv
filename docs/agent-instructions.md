# 공통 작업 지침

AGENTS.md에서 이 문서를 읽도록 안내하며 CLAUDE.md는 AGENTS.md를 import한다. 공통 절차의 상세 내용은 이 문서를 원본으로 관리한다. 스킬 자동 등록 상태는 [작업 기록](work-log.md)을 확인한다.

## 시작과 범위

- 작업 기록에서 현재 단계와 승인 범위를 먼저 확인한다. 구조 변경은 개발 설계, 검증 작업은 검증 전략을 읽는다.
- 현재 단계만 수행하고 종료 시 결과를 보고한다. 다음 단계는 사용자와 합의한다. 전체 계획 실행 요청을 모든 단계의 일괄 실행 승인으로 해석하지 않는다.
- 예정 파일·명령과 실제 구현 상태를 구분한다. 전역 에이전트 설정을 변경하지 않는다.

## 제품 규칙

- Astro + TypeScript 정적 페이지와 Tailwind CSS를 사용한다.
- 콘텐츠·표시·테마·UI를 분리한다. 컴포넌트에서 config를 직접 import하거나 API를 호출하지 않는다.
- 샘플임을 알 수 있는 최소 콘텐츠만 작성한다. 참고 PDF에서 실제 개인정보·경력·성과·이미지를 복사하지 않는다.
- 반복 항목은 제목·순서와 독립적인 ID를 갖는다. 문장 강조는 구조화된 데이터로 표현한다.
- 누락 날짜·경력 개월 수를 생성하지 않는다. 종료일 누락을 현재 재직으로 해석하지 않는다.
- 로딩 실패를 빈 데이터나 샘플로 대체하지 않는다.
- 폰트·간격·색상·너비는 콘텐츠와 같은 config 폴더의 별도 테마 파일에서 관리한다. Tailwind 클래스는 정적으로 선언한다.

## 테스트 사전 검토 — 사용자 요청에 따른 필수 규칙

- 테스트 신규 작성·수정·삭제 전 목적·입력·기대 결과·실패 조건을 논의한다.
- 실제 코드 초안 또는 diff를 대화에 제시하고 명시적 승인 후 파일에 반영한다.
- fixture, helper, snapshot, 기준 이미지, 테스트 역할의 임시 스크립트와 브라우저 평가 코드에도 동일하게 적용한다.
- 계획·시나리오 승인만으로 코드 승인을 추정하지 않는다. 코드 수정이 필요하면 diff를 다시 확인받는다.
- 승인 전 테스트 파일을 임시 경로에도 저장하지 않는다. 응답이 없다는 이유로 승인 처리하지 않는다.
- 기존 승인된 테스트 실행, 설치된 도구의 타입·lint·포맷 검사·빌드는 재승인 없이 수행한다.
- 테스트 삭제·skip·기대값 완화·snapshot 갱신으로 실패를 숨기지 않는다.
- 지침은 작업 규칙이며 자동으로 파일 쓰기를 차단하는 보안 장치가 아니다.

## 커밋 규칙

### 하나의 목적과 완결된 변경

- 파일 개수가 아니라 변경 목적을 기준으로 커밋을 나눈다. 기능과 이에 필요한 설정·문서·승인된 테스트는 함께 묶을 수 있다.
- 관련 없는 정리나 전체 포맷 변경은 분리한다. 새 스킬과 이를 연결하는 문서처럼 서로 의존하는 변경은 함께 커밋한다.
- 각 커밋에서 참조 파일이 존재하고 해당 단계에서 실행 가능한 상태를 유지한다. 미구현 단계의 예정 경로·명령은 예정임을 명시한다.
- 승인 대기나 미구현 부분이 남아 있으면 독립적으로 완료된 범위만 분리하고, 전체 작업이 완료된 것처럼 표현하지 않는다.

### 한글 제목과 필요한 본문

- 제목은 `유형: 구체적인 변경 내용` 형식을 사용한다.
- 유형은 `기능`, `수정`, `정리`, `문서`, `설정`, `도구`, `테스트`, `되돌림` 중 목적에 맞게 선택한다. `정리`는 동작을 바꾸지 않는 구조 개선에 사용한다.
- `수정 완료`, `작업 반영`, `업데이트`처럼 변경 내용이 드러나지 않는 제목은 피한다. 코드 식별자와 도구 이름은 원래 표기를 유지한다.
- 단순 변경은 제목만으로 충분하다. 동작·설정 변경은 본문에 이유와 실제 검증 결과를 기록한다. 관련 검사를 수행하지 못했다면 사유도 적는다.
- 예시는 표현 형식의 참고이며 검증 결과를 그대로 복사하지 않는다.

제목 예시:

```text
설정: Astro와 Tailwind 개발 환경 구성
기능: 설정에서 이력서 데이터를 읽는 로더 추가
수정: 프로젝트 없는 경력의 빈 여백 제거
문서: 테마 설정 변경 방법 설명
```

본문은 필요한 경우 다음 항목을 짧게 작성한다.

- 이유: 해결하려는 문제와 변경 후 동작
- 검증: 실제 실행한 명령·확인 절차와 결과
- 미검증: 관련 검사 중 미실행 항목과 이유

### 커밋 전 확인

- 변경 목록과 staged diff를 검토하고 `git diff --cached --check`를 실행한다. 의도한 파일과 변경 부분만 포함한다.
- 변경 범위에 필요한 타입·lint·승인된 테스트·빌드 검사를 수행한다. 문서만 변경한 경우에는 문서 참조·내용과 해당 스킬 형식을 확인한다.
- 비밀값, 실제 이력서 PDF, 생성 파일, 관련 없는 사용자 변경을 포함하지 않는다.
- 알려진 검사 실패를 숨긴 채 완료 커밋을 남기지 않는다. 실패 원인을 설명하고 해결하거나 사용자와 처리 방향을 합의한다.

### 테스트 승인과 로컬 커밋

- 커밋 권한은 테스트 코드 작성·수정·삭제 승인까지 포함하지 않는다. 테스트는 앞의 사전 검토 절차를 그대로 따른다.
- 승인된 구현 범위의 작업과 필요한 검증이 끝나면 로컬 커밋은 매번 재확인하지 않고 진행한다. 단계 경계를 넘는 작업은 별도로 합의한다.

### 이력 보존과 종료 보고

- 기본적으로 후속 커밋으로 수정한다. `amend`, `rebase`, 강제 push 등 이력 변경은 별도 요청이 있을 때만 수행한다.
- 원격 push는 별도 요청 없이 수행하지 않는다.
- 커밋 후 해시·한글 제목·검증 결과·남은 변경을 보고한다. 사용자 변경이 남아 있으면 작업 트리가 깨끗하다고 보고하지 않는다.

## 반복 작업과 종료

변경 계획에는 cv-plan-change, 테스트 코드 검토에는 cv-review-tests, 검증에는 cv-verify-change 스킬을 사용한다. 원본은 `.agents/skills`에서 편집하며 `.claude/skills`는 같은 원본을 가리키는 개별 상대 링크다.

변경 내용, 실제 수행한 검사·결과, 미검증 사항, 다음 검토 대상을 기록한다. 테스트 미작성·미실행을 통과로 표시하지 않는다. 자동 검사와 사람의 화면 검토를 구분하며 배포는 별도 요청 없이 수행하지 않는다.
