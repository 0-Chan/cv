# 변경 단위 계획

경로는 저장소 루트 기준이다. AGENTS.md의 현재 단계와 docs/development.md를 읽고 대화에서 승인된 범위를 확인한다. 과거 변경은 필요한 경우 Git 이력에서 확인한다.

1. 실제 파일과 현재 단계, 사용자의 요청 범위를 확인한다. 예정 구조와 구현 상태를 구분한다.
2. 콘텐츠·표시·테마·로더·UI 중 변경 책임을 정한다. 컴포넌트로 데이터 접근을 옮기지 않는다.
3. 검토 가능한 최소 변경 단위, 입력·출력·완료 조건·미결정을 제시한다.
4. 변경으로 생길 구체적인 실패 위험과 기존 검증 범위를 확인하고, 충분한 근거를 얻는 가장 단순한 검증 수단을 고른다. 관련 제품 동작은 docs/verification.md의 요구사항 ID에 연결하되, ID마다 테스트 파일을 만들거나 모든 경계값을 자동화할 필요는 없다. 기존 검사·직접 실행으로 부족한 경우에만 새 회귀 테스트를 제안하며, 필요성 판단과 코드 사전 검토는 cv-review-tests를 따른다.
5. 합의된 범위와 미결정 사항을 대화에서 정리한다. 단계 상태가 바뀌면 AGENTS.md의 현재 단계·다음 작업만 갱신한다. README에 에이전트 상태를 기록하지 않으며 다음 단계 요청 없이 단계 경계를 넘지 않는다.

산출물은 이번 변경 범위, 필요한 결정, 검증 대상, 종료 조건이다. 이미 승인된 범위를 반복 승인받지 않는다. 계획만 요청받았다면 파일을 변경하지 않는다.

완료 조건은 사용자가 요구한 동작과 이를 확인할 증거로 정한다. 테스트 개수·coverage 목표나 새 테스트 작성을 관성적으로 완료 조건에 넣지 않는다. 단순 설정·문서 변경에는 해당 도구 실행이나 참조 확인으로 충분할 수 있다. 자동화가 필요하더라도 fixture·mock·별도 빌드 환경의 유지 비용을 먼저 설명하고, 단계 마무리를 이유로 테스트 기반 시설을 확장하지 않는다.

## 단계별 진행

| 단계 | 작업 | 종료 조건 |
|---|---|---|
| 1. 하네스 | 지침·제품 설계·검증 기준·공통 스킬 | 문서·참조 검사, 사용자 검토 |
| 2. 개발 환경 | Astro 최소 골격, Tailwind·Biome·타입 검사·Vitest 설정 | 도구 적용 범위와 실행 결과 보고 |
| 3. 데이터 | 모델·검증·로더·콘텐츠/표시/테마 설정 | 데이터 계약 검토, 기존 검사와 필요한 직접 확인 |
| 4. 최소 화면 | 프로필·소개·경력 한 묶음 | 데이터 교체·반응형 화면 검토 |
| 5. 전체 화면 | 기술·학력·자격·누락 데이터 처리 | 전체 요구사항 대응 검증 |
| 6. 마무리 | 편집법·API 전환 문서·검증 증거 | 미검증 사항까지 포함한 완료 보고 |

각 단계는 별도 작업 단위다. 하네스 단계에서 패키지 설치·제품 구현·테스트 작성·CI·hook 설치로 넘어가지 않는다. 사용자가 다음 단계를 요청하면 합의한 범위는 재승인 없이 진행하되 테스트 코드는 사전 검토한다.
