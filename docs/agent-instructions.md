# 공통 작업 지침

AGENTS.md에서 이 문서를 읽도록 안내하며 CLAUDE.md는 AGENTS.md를 import한다. 공통 절차의 상세 내용은 이 문서를 원본으로 관리한다. 스킬 자동 등록 상태는 [작업 기록](work-log.md)을 확인한다.

## 시작과 범위

- 작업 기록에서 현재 단계와 승인 범위를 먼저 확인한다. 구조 변경은 개발 설계, 검증 작업은 검증 전략을 읽는다.
- 현재 단계만 수행하고 종료 시 결과를 보고한다. 다음 단계는 사용자와 합의한다. 전체 계획 실행 요청을 모든 단계의 일괄 실행 승인으로 해석하지 않는다.
- 예정 파일·명령과 실제 구현 상태를 구분한다. 전역 에이전트 설정을 변경하지 않는다.

## 제품 규칙

- Astro + TypeScript 정적 페이지와 Tailwind CSS를 사용한다.
- 콘텐츠·표시·테마·UI를 분리한다. 컴포넌트에서 config를 직접 import하거나 API를 호출하지 않는다.
- 샘플임을 알 수 있는 최소 콘텐츠만 작성한다. 참고 PDF에서 실제 개인정보·경력·성과·이미지를 복사하지 않는다.
- 반복 항목은 제목·순서와 독립적인 ID를 갖는다. 문장 강조는 구조화된 데이터로 표현한다.
- 누락 날짜·경력 개월 수를 생성하지 않는다. 종료일 누락을 현재 재직으로 해석하지 않는다.
- 로딩 실패를 빈 데이터나 샘플로 대체하지 않는다.
- 폰트·간격·색상·너비는 콘텐츠와 같은 config 폴더의 별도 테마 파일에서 관리한다. Tailwind 클래스는 정적으로 선언한다.

## 테스트 사전 검토 — 사용자 요청에 따른 필수 규칙

- 테스트 신규 작성·수정·삭제 전 목적·입력·기대 결과·실패 조건을 논의한다.
- 실제 코드 초안 또는 diff를 대화에 제시하고 명시적 승인 후 파일에 반영한다.
- fixture, helper, snapshot, 기준 이미지, 테스트 역할의 임시 스크립트와 브라우저 평가 코드에도 동일하게 적용한다.
- 계획·시나리오 승인만으로 코드 승인을 추정하지 않는다. 코드 수정이 필요하면 diff를 다시 확인받는다.
- 승인 전 테스트 파일을 임시 경로에도 저장하지 않는다. 응답이 없다는 이유로 승인 처리하지 않는다.
- 기존 승인된 테스트 실행, 설치된 도구의 타입·lint·포맷 검사·빌드는 재승인 없이 수행한다.
- 테스트 삭제·skip·기대값 완화·snapshot 갱신으로 실패를 숨기지 않는다.
- 지침은 작업 규칙이며 자동으로 파일 쓰기를 차단하는 보안 장치가 아니다.

## 반복 작업과 종료

변경 계획에는 cv-plan-change, 테스트 코드 검토에는 cv-review-tests, 검증에는 cv-verify-change 스킬을 사용한다. 원본은 `.agents/skills`에서 편집하며 `.claude/skills`는 같은 원본을 가리키는 개별 상대 링크다.

변경 내용, 실제 수행한 검사·결과, 미검증 사항, 다음 검토 대상을 기록한다. 테스트 미작성·미실행을 통과로 표시하지 않는다. 자동 검사와 사람의 화면 검토를 구분하며 배포는 별도 요청 없이 수행하지 않는다.
