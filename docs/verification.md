# 제품 검증 기준

현재는 React TSX의 프로필·소개·경력·기술·학력·자격, 테마 연결, 데이터·설정 모델, 빌드 시 로더와 검사 도구가 구현되어 있다. 날짜·재직 여부, YAML 작성·오류 안내, 경력 콘텐츠 변환, 필수 콘텐츠·빈 값·링크·이미지 입력, Markdown·YAML 핵심 변환, 설정·로더의 단위 테스트가 있다. 브라우저 자동화는 아직 없다.

## 요구사항 대응표

아래 수단은 선택 가능한 검증 방법이며, 모든 항목에 자동 테스트나 별도 테스트 환경이 필요한 것은 아니다. 기존 검사와 직접 실행으로 충분한 동작은 그 결과로 확인한다. 테스트 개수나 coverage 수치를 완료 기준으로 삼지 않는다.

데이터 계약과 로더는 구현되어 있다. D2의 필수 텍스트 누락·빈 값·날짜 형식·용도별 링크 규칙과 O2의 재직·기간 데이터 규칙은 단위 테스트로 검증하며, YAML 링크·기술 매핑 및 섹션 생략, 오류의 필드 경로, 중복 키의 행·열 안내도 검증한다. 경력의 요약만·프로젝트만·둘 다 있는 입력에서 내용 분리를 검증하고, 프로젝트 핵심 역할 필수·이슈별 내용 분리·중첩 Markdown 오류 경로와 빈 이슈·해결 방향·성과도 검사한다. 로고·배지의 주소·대체 텍스트 검증과 변환, 이미지·확인 링크 생략도 검사한다. 실제 이력서의 로컬 빌드 화면은 Chrome에서 직접 확인했으며 범위와 남은 항목은 아래 화면 구현 검증 범위에 기록한다. 아래 수단은 선택 가능한 검증 방법이며 테스트 코드의 사전 승인이 아니다.

| ID | 확인할 동작 | 제안 수단 |
|---|---|---|

| D4 | 강조는 strong으로 표현; 일반 텍스트의 HTML 문자를 실행하지 않음 | 렌더 결과 |

| O1 | 로고·배지·날짜·링크 없이 정렬 유지; 빈 링크 없음 | 브라우저 + 시각 검토 |
| O2 | 종료일 없음과 현재 재직 구분; 제공 연월의 입·퇴사월을 포함해 근속 기간 계산; 현재 재직만 서울 기준 빌드월 사용; 누락 날짜·연도만 있는 날짜는 추정 없이 근속 기간 생략; 웹·PDF·Markdown 결과 일치 | Vitest + 렌더 결과 |
| T1 | 테마 폰트·크기·굵기·줄 높이·간격·색상·너비·종이 설정 변경이 실제 스타일에 반영 | 생성 명령 + 브라우저 computed style |

## 검사 명령

| 명령 | 역할 |
|---|---|
| npm run check | astro check: Astro·TypeScript 검사 |
| npm run lint | Biome lint |
| npm run format:check | Biome format 검사, 수정 없음 |
| npm run format | 명시적 포맷 수정; 미승인 테스트 변경 제외 |
| npm test | 승인된 Vitest 테스트 |
| npm run build | 정적 빌드 |
| npm run verify:static | 현재 제공하는 타입·lint·포맷 검사·빌드. 테스트는 포함하지 않음 |
| npm run verify:commit | 타입·lint·포맷·Vitest 검사; pre-commit에서 실행 |
| npm run verify | verify:commit 통과 후 정적 빌드 |
| npm run prepare | 이 저장소의 Husky hook 등록 |

Vitest는 `src/models/resume.test.ts`의 날짜·재직 여부와 `src/data/yaml-source.test.ts`의 YAML 작성·오류 안내, `src/data/experience-content.test.ts`의 경력 콘텐츠 분리와 역할 생략, `src/data/input-validation.test.ts`의 필수 콘텐츠·빈 값·링크·이미지 입력을 검사한다. 입력 오류는 예외 종류와 작성 필드 경로를 확인하고 정상 입력은 공통 모델 검증 후 값 보존을 확인한다. 테스트 파일이 없으면 실패하며 passWithNoTests를 사용하지 않는다.

`src/data/markdown-yaml.test.ts`는 서식·중첩·공백 보존, 문단형·목록형 소개, HTML·표·실행 URL 오류의 프로젝트 필드 경로, 연락처 매핑을 7개 사례로 검사한다. D4의 데이터 변환을 확인하며 실제 HTML 렌더링과 실행 방지는 검증하지 않았다.

`src/data/resume.test.ts`와 `src/data/local-source.test.ts`는 설정값 보존과 선택 목록 정규화, 섹션 중복·누락 및 테마 오류 경로, 콘텐츠 타입 오류의 원본 값 미노출, 공급 오류 전파, 빈 YAML 오류를 10개 사례로 검사한다. 설정·공급 모듈 또는 YAML 원문을 mock하며 실제 파일 누락과 실패 빌드 재현은 아직 검증하지 않았다.

잘못된 입력을 오류로 처리해야 해당 테스트가 통과한다. 실제 config의 검증 오류는 정적 페이지 생성 중 빌드로 전파된다. `npm run build` 자체는 Vitest를 실행하지 않으며 전체 검증은 `npm run verify`로 수행한다.

Husky의 pre-commit은 verify:commit을, pre-push는 build를 실행한다. commit-msg는 한글 커밋 제목 형식을 검사한다. hook 도입 당시 직접 실행으로 기존 86개 테스트·정적 검사·빌드 통과, 정상 제목 통과와 빈 제목의 종료 코드 1을 확인했다. 별도 hook 테스트 코드 대신 직접 실행과 실제 커밋·push로 연결을 확인했다.

Astro build는 타입 검사를 대체하지 않는다. Biome는 TS·JSON·CSS·Astro 및 Tailwind 구문을 대상으로 설정한다. Astro 전체 지원은 실험적이므로 명시적으로 활성화하고 적용 범위를 확인한다. 재현된 오탐만 해당 규칙·파일 범위로 제한해 사유를 기록한다.

Vitest는 데이터·정규화 규칙을 검사한다. Playwright와 axe는 각각 반복적인 화면 검증과 접근성 자동 검사가 필요할 때 검토할 후보이며, 현재 설치된 도구나 도입 확정 사항이 아니다. 브라우저 fixture를 도입한다면 일반 배포 경로에 노출하지 않는다. 초기 스크린샷은 수동 검토 증거로 사용하며 자동 시각 회귀 기준은 필요성이 확인된 경우 별도 코드 검토 후 도입한다.

변경과 관련된 요구사항의 확인 여부를 검토한다. 미검증 동작은 그대로 밝히고, 빈 테스트나 passWithNoTests로 통과 처리하지 않는다.

## YAML 전환 검증 범위

기존 날짜·재직 여부 테스트는 유지한다. 링크·기술·연락처 매핑, 섹션 생략, 필드 오류와 중복 키 위치, 경력 콘텐츠 분리, 필수 텍스트·빈 값·링크·이미지 입력을 검증한다. Markdown은 서식·중첩·공백과 소개 문단·목록 변환, HTML·표·실행 URL 오류를 핵심 사례로 검증한다. 줄바꿈 문법별 검사와 URL 종류별 반복 검사는 추가하지 않는다. 로더의 빈 YAML·콘텐츠 타입 오류의 원본 값 미노출·공급 오류 전파도 검증한다. 실제 실패 빌드 확인은 남아 있다.

Biome 검사 범위에는 src 아래 YAML도 포함한다. 정상 빌드 성공과 오류 입력에 대한 실패 빌드 검증을 구분한다. 기본 빌드의 배포 자산에 원본 YAML이나 테스트 fixture가 노출되지 않는지도 확인한다.


## 화면 구현 검증 범위

아래는 내보내기 기능 도입 전의 검증 범위다. 현재의 추가 클라이언트 스크립트와 생성 PDF는 아래 내보내기 항목에서 구분한다.

실제 이력서를 빌드해 이름 h1, 다섯 섹션 h2, 회사·기술 분류·기관·자격 h3, 프로젝트 h4와 strong 강조를 확인했다. 재직 이력 3개, 프로젝트 4개, 회사·프로젝트의 수행 내용 19개가 소속에 맞게 한 번씩 출력되며 프로젝트 소개가 담당 역할보다 먼저 나온다. 샘플 문구는 남아 있지 않다. 생성 HTML에는 script와 astro-island가 없으며 React 클라이언트 파일이 산출물에 존재하더라도 페이지에서 참조하지 않는다. 산출물 목록에 원본 YAML·테스트 fixture·참고 PDF는 없다.

루트와 /cv 하위 경로 빌드에서 로고 3개·배지 2개의 주소와 대체 텍스트를 확인했고, 두 산출물의 이미지 파일은 빌드 당시의 public 자산과 일치한다. /cv 빌드의 canonical·CSS 경로도 확인했다. 명시적인 현재 재직 표시와 제공된 날짜를 유지하며, 날짜가 없는 자격에는 취득 항목이 출력되지 않는다. 제공되지 않은 확인 링크와 경력 개월 수는 생성하지 않는다. 실제 콘텐츠로 타입·Biome·기존 테스트 86개와 두 경로의 빌드가 통과했다.

기존 배포의 GitHub Actions 타입·Biome·기존 테스트 86개·정적 빌드·Pages 배포가 통과했다. 공개 주소 https://0-chan.github.io/cv/의 HTML·CSS·이미지 5개가 HTTPS로 HTTP 200을 반환하고 canonical·CSS·이미지 경로가 `/cv/`를 사용하는 것을 확인했다. 원격 배포 상태는 해당 커밋의 GitHub Actions 결과와 공개 산출물로 확인한다.

한 열 UI의 Astro 타입·Biome·기존 테스트 86개·루트 및 `/cv/` 빌드가 통과했다. `/cv/` 산출물을 로컬 preview로 제공해 Chrome 앱의 DevTools 반응형 모드에서 320·390·768·1440px을 직접 확인했다. 실제 콘텐츠의 긴 프로젝트명·영문 자격명·프로필 URL이 잘리지 않고 줄바꿈되며 가로 넘침이 보이지 않았다. 프로젝트 없는 회사와 취득일 없는 자격을 확인했다. GitHub 링크의 Tab 포커스 테두리와 200% 확대의 소개·경력 본문, 인쇄 미리보기·forced-colors 활성 모드의 단색 제목도 확인했다. 검증 후 확대·기기 모드·고대비 에뮬레이션은 해제했다. YAML diff에서는 문장·수치·날짜를 유지하고 강조 기호만 변경한 것을 확인했다. 이 화면 검토는 로고·배지를 왼쪽으로 옮기기 전에 수행했다.

최신 로고 배치의 로컬 타입·Biome·기존 테스트 86개·루트 빌드와 GitHub Actions의 검사·Pages 배포가 통과했다. 산출물에서 회사명 뒤에 로고 3개가 각각 8px 간격으로 이어지고, 자격 배지 2개는 모든 화면에서 텍스트 왼쪽에 배치하는 구조임을 확인했다. 공개 사이트를 Chrome에서 직접 열어 데스크톱과 320px 에뮬레이션의 회사명 바로 옆 로고·자격 텍스트 왼쪽 배지·긴 자격명 줄바꿈을 확인했다. 기기 모드와 DevTools는 검토 후 닫았다.

브라우저 확장 연결의 `The browser access host is unavailable` 오류는 남아 있지만 Chrome 앱의 화면·접근성 트리를 통한 직접 검토는 가능했다. 위 검증은 데스크톱 Chrome의 로컬 빌드·에뮬레이션 결과이며 실기기나 다른 브라우저의 검증은 아니다. 설정 교체·섹션 순서와 숨김·빈 섹션·이미지 생략·더 많은 태그 조건의 별도 화면, 실제 실패 빌드, 링크의 실제 외부 접근은 아직 미검증이다. 별도 fixture나 임시 테스트 코드는 작성하지 않았고 개인 도메인 연결도 수행하지 않았다.

## 종이 배경과 개발 패널

아래의 script 미포함 확인은 종이 배경 도입 당시의 결과다. 내보내기 도입 후에는 인쇄·메뉴 조작용 스크립트만 추가된다.

종이 배경의 타입·Biome·기존 테스트 86개·루트 및 `/cv/` 빌드를 확인했다. `rg -n 'dev:paper-texture|PaperTexturePanel|paper-texture-dev|타일 경계 보기|백상지로 되돌리기|cv-paper-tools|@react-refresh' dist`는 일치 없음(종료 코드 1)을 반환했다. 프로덕션 HTML에는 script·astro-island가 없고 종이 배경 CSS가 포함된다. 로컬 개발 HTML·동적 import·React 초기화·패널 모듈의 응답과 프로덕션 preview의 HTML·CSS 200, 개발 모듈 경로 404를 확인했다.

제공된 백상지 SVG를 Sharp 렌더러로 미색 배경에 multiply 합성했을 때 가장 어두운 색은 #C5C4C1이었다. 이 기준에서 본문 #171717은 10.28:1, 보조 글자 #4B4B4B는 5.00:1, 링크 #7C3200은 5.21:1이다. 큰 제목 그라데이션의 양 끝 #A34200·#B44900은 각각 3.61:1·3.09:1이다. 필터와 프리셋 값은 유지하고 글자색만 보정했다. 이는 독립 SVG 렌더러의 측정이며 실제 브라우저·배율별 결과를 보장하지 않는다.

현재 Chrome URL에서 컴퓨터 사용이 허용되지 않아 브라우저 검증 세션이 종료됐다. 실제 화면의 질감·타일 이음새·조절 응답성, 패널 단축키·드래그·위치 복원·초기화·클립보드·키보드 탐색, 375px 접힘 상태와 성능은 아직 미검증이다. 프로덕션의 패널 제외 확인과 실제 개발 패널 조작 확인을 구분한다. 새 테스트 코드·fixture·기준 이미지는 추가하지 않았다.

## 내보내기 검증 범위

X1~X3의 타입·Biome·기존 Vitest 86개와 루트 및 `/cv/` 정적 빌드가 통과했다. 새 테스트·fixture는 작성하지 않았다. 생성 HTML에서 1024px 이상 표시용 클래스, PDF·Markdown의 `/cv/` 링크와 프로필 이름을 사용한 download 파일명을 확인했다. 인쇄 CSS는 html·body에 #fff를 지정하고 Export·종이 패널·개발 도구를 숨긴다. HTML·JS에는 PDF 생성 도구·한글 글꼴 소스·개발 패널 코드가 포함되지 않는다. React 클라이언트 파일이 산출물에 존재하더라도 페이지에서 참조하지 않으며 메뉴·인쇄용 작은 스크립트만 실행한다.

`pdfinfo`에서 A4 4페이지, `pdffonts`에서 나눔고딕 Regular·Bold의 임베딩과 Unicode 매핑, `pdfinfo -url`에서 프로필 링크를 확인했다. `pdftotext -layout`으로 실제 콘텐츠와 한글을 추출했고 `pdftoppm -scale-to 1400 -png`로 모든 페이지를 펼쳐 제목·이미지·줄바꿈·페이지 경계의 잘림 여부를 직접 검토했다. 한글 어절 중간에 붙던 하이픈을 제거했고 모든 페이지의 빈 배경 지점은 RGB 255·255·255다. PDF 렌더링 검토는 브라우저 화면 검증과 구분한다.

Markdown 원문에서 다섯 섹션과 회사·프로젝트의 제목 계층, 소개→역할→성과 순서, 강조와 링크·날짜 보존, 장식 이미지 제외를 확인했다. 표시·순서·빈 섹션 처리는 화면·PDF·Markdown이 같은 함수를 사용함을 코드로 확인했으며 별도 설정 교체 fixture는 만들지 않았다. `/cv/` preview의 페이지·PDF·Markdown은 각각 HTTP 200이며 PDF와 Markdown의 Content-Type은 application/pdf·text/markdown이다. 콘텐츠 변경 후 회사 정보 헤더의 분리와 기술 분류 제목만 페이지 끝에 남는 현상을 재현해 수정하고 PDF 4페이지를 다시 렌더링해 확인했다. 브라우저 접근 제한으로 실제 클릭 다운로드·키보드·모바일 숨김·인쇄 미리보기와 물리 프린터 출력은 미검증이다. 원격 배포 확인은 GitHub Actions 결과와 공개 파일 응답으로 구분한다.

## 프로젝트 이슈 구조 전환

프로젝트 주요 기여와 이슈의 제목·문제 설명·해결 방향·성과를 필수로 관리한다. 프로젝트별 기술 스택 필드는 지원하지 않으며 웹·PDF·Markdown에도 출력하지 않는다. 회사 수준 업무 요약과 프로젝트 없는 경력은 유지한다.

현재 실제 콘텐츠 2개 프로젝트·4개 이슈를 표시한다. AI 이용 환경 통합은 프로젝트 소개에 포함하고 로딩·오류·데이터 없음 상태 처리와 신규 분석 기능 대응 구조에 관한 항목은 삭제했다. 타입·Biome lint·포맷 검사·루트 및 /cv 빌드가 통과했다. 생성 HTML에서 프로젝트 h4 2개·이슈 h5 4개·단계 h6 8개와 해결 방향 ol 4개를 확인했다. 웹·PDF·Markdown의 이슈 번호와 제목은 `이슈1. 제목` 형식의 제목 하나로 표시하며 장식 구분자 `—`는 사용하지 않는다. Markdown의 소개·h5 이슈 제목·h6 단계 제목과 번호/글머리표 목록을 확인했다. 현재 PDF는 A4 5페이지이며 모든 페이지를 이미지로 렌더링해 제목·목록·이미지·페이지 경계를 직접 확인했다. PDF 이슈 제목은 후속 본문과 이어지도록 보호한다. 모바일 메타 정보의 세로 배치와 긴 제목의 줄바꿈 규칙은 소스·생성 CSS로 확인했으며 실제 브라우저 화면 검토와 구분한다.

프로젝트 내부의 첫 이슈 간격 12px·이슈 사이 32px·단계 8px·목록 4px, 외부 묶음의 프로젝트 48px·회사 64px·섹션 80px·기술 분류 40px를 생성 HTML·CSS로 확인했다. 학력·자격의 dividedItem 72px는 부모 gap과 항목 padding에 각각 절반씩 적용한다. PDF는 같은 테마를 pt로 변환하고 마지막 목록 항목의 여백을 제거했다. 프로젝트 설명·기술 스택·핵심 역할은 모두 14px 보조색으로 통일하고 특정 문구의 Markdown strong을 유지한 것을 생성 HTML과 PDF에서 확인했다. 타입·Biome·기존 91개 테스트·두 경로의 빌드가 통과했으며 PDF 5페이지의 스타일·번호·제목과 페이지 경계를 검토했다. 로더·Markdown 변환·테스트 코드는 변경하지 않았다. 실제 브라우저 화면과 모바일 넘침은 아직 확인하지 못했다.

사용자가 실제 diff를 승인한 테스트 세 파일만 새 계약으로 변경했다. 회사 요약·프로젝트 내용 분리 검사를 유지하고 역할 생략 허용 검사는 핵심 역할 필수 검사로 전환했다. 두 이슈의 설명·해결 방향·성과 보존과 중첩 Markdown 오류 위치, 빈 이슈·해결 방향·성과를 검증한다. 구형 입력으로 실패하던 9개 사례는 새 계약으로 전환한 뒤 통과했으며 전체 결과는 7개 파일·91개 테스트 통과다. 별도 fixture 파일·snapshot·테스트 도구는 추가하지 않았고 기존 highlights 형식을 임시 허용하거나 테스트를 skip하지 않았다. 실제 브라우저의 반응형·키보드·인쇄 미리보기는 미검증이다.
