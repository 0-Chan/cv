# 변경 단위 계획

경로는 저장소 루트 기준이다. AGENTS.md, docs/work-log.md, docs/development.md를 읽는다.

1. 실제 파일과 현재 단계, 사용자의 요청 범위를 확인한다. 예정 구조와 구현 상태를 구분한다.
2. 콘텐츠·표시·테마·로더·UI 중 변경 책임을 정한다. 컴포넌트로 데이터 접근을 옮기지 않는다.
3. 검토 가능한 최소 변경 단위, 입력·출력·완료 조건·미결정을 제시한다.
4. 검증은 docs/verification.md의 요구사항 ID에 연결한다. 새 테스트는 시나리오와 코드 초안 검토를 거치며 아직 작성하지 않는다.
5. 합의된 사항만 작업 기록에 남긴다. 다음 단계 요청 없이 단계 경계를 넘지 않는다.

산출물은 이번 변경 범위, 필요한 결정, 검증 대상, 종료 조건이다. 이미 승인된 범위를 반복 승인받지 않는다. 계획만 요청받았다면 파일을 변경하지 않는다.
